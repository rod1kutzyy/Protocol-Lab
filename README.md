# Protocol Lab

Protocol Lab — локальное веб-приложение для исследования недокументированных
бинарных протоколов устройств поверх TCP/IPv4. Оно восстанавливает потоки из
PCAP/PCAPNG, помогает сопоставить байты с действиями пользователя, описать формат
сообщений и проверить модель на нескольких записях трафика.

В приложении доступны HEX/ASCII, поиск и сравнение диапазонов, переход к исходным
пакетам, журнал действий, наблюдения и гипотезы, версионируемые JSON-модели,
проверка с контрпримерами и локальный анализатор кандидатов в правила протокола.
Результаты можно выгрузить в Markdown и JSON, а исследование целиком — в переносимый
ZIP-архив. После установки зависимостей приложение работает без интернета;
данные обрабатываются локально. Для исследования нужен незашифрованный трафик.

## Запуск

Готовый скрипт [run.py](run.py) запускает PostgreSQL, API и веб-интерфейс одной
командой. Команды ниже выполняются из корня репозитория.

### Что установить

- **Python 3.12 или 3.13**.
- **uv** для установки Python-зависимостей из `backend/uv.lock`.
- **Node.js 22.12+ и npm** для интерфейса.
- **Docker с Compose v2** для локального PostgreSQL 17. На macOS и Windows подойдёт
  Docker Desktop; на Linux — Docker Engine с плагином Compose.

Команды `python`, `uv`, `node`, `npm` и `docker` должны быть доступны в `PATH`.
На macOS/Linux вместо `python` может потребоваться `python3`, на Windows — `py`.
Перед запуском включите Docker. На Windows скрипт также умеет запускать Docker Desktop
самостоятельно.

### Первый запуск

```sh
python run.py --setup
```

Скрипт установит зависимости из lock-файлов, при отсутствии `.env` создаст его
из [.env.example](.env.example) со случайным паролем БД, загрузит образ PostgreSQL,
поднимет базу и применит миграции Alembic. Затем запустит FastAPI и Vite.
Первый запуск требует интернета. Существующий `.env` сохраняется; если вы создали
его вручную, заранее замените `CHANGE_ME` одинаковым паролем в обеих настройках БД.

После сообщения об успешном запуске откройте:

- [Веб-интерфейс](http://127.0.0.1:5173).
- [Документацию API (Swagger)](http://127.0.0.1:8000/docs).

### Повторный запуск и остановка

```sh
python run.py
```

Повторный запуск использует установленные зависимости и локальный образ PostgreSQL.
После изменения lock-файлов снова выполните команду с `--setup`.

Для остановки API и интерфейса нажмите **Ctrl+C** в терминале. PostgreSQL останется
работать, данные сохранятся. При необходимости остановите базу отдельно:

```sh
docker compose stop postgres
```

### Свой PostgreSQL

Чтобы использовать уже запущенную локальную БД без Docker, укажите
`PROTOCOL_LAB_DATABASE_URL` в корневом `.env` или переменных окружения, например:

```dotenv
PROTOCOL_LAB_DATABASE_URL=postgresql+psycopg://protocol_lab:YOUR_PASSWORD@127.0.0.1:5432/protocol_lab
PROTOCOL_LAB_PROJECT_ROOT=./projects
```

Базу и пользователя нужно создать заранее. Скрипт применит миграции и запустит
приложение; Docker в этом режиме не нужен:

```sh
python run.py --setup --external-db
```

В дальнейшем достаточно `python run.py --external-db`.

## Основной путь пользователя

1. **Создать проект.** В верхней панели откройте «Проекты», введите название
   и нажмите «Создать проект»; существующий проект можно выбрать из списка.
2. **Загрузить запись.** В разделе «Данные» выберите PCAP/PCAPNG, нажмите
   «Импортировать запись» и дождитесь завершения. Затем нажмите «Восстановить TCP».
   При наличии журнала действий импортируйте его в CSV/JSON и настройте поправку часов.
3. **Исследовать обмен.** Откройте TCP-соединение и выберите направление A → B
   или B → A. В «Исследовании» просмотрите HEX/ASCII, найдите и сравните диапазоны,
   перейдите к исходным пакетам. Сохраните наблюдения, свяжите байты с действиями
   и сформулируйте гипотезы.
4. **Описать модель.** В разделе «Модель» задайте границы сообщений, затем поля
   и правила в JSON. Сохраните версию и проверьте разбор на выбранном потоке.
5. **Проверить на корпусе.** В «Проверке» сохраните набор записей и фильтров,
   выберите версию модели и запустите проверку. Изучите покрытие, ошибки,
   неизвестные и неоднозначные случаи. Откройте байты контрпримера, исправьте модель,
   сохраните новую версию и сравните результаты повторного запуска.
6. **Экспортировать исследование.** В «Результатах» скачайте Markdown-отчёт,
   JSON-модель, результаты проверки или ZIP проекта. ZIP можно восстановить
   через меню «Проекты» на другой локальной установке.

Для поиска правил можно дополнительно открыть «Исследование» → «Анализатор»
и выбрать сохранённый корпус. Он предлагает кандидатов с примерами и противоречиями;
поддерживаемые кандидаты можно сохранить как черновик модели и проверить на корпусе.
Найденное совпадение само по себе не доказывает смысл поля или команды.

Прогресс длительных операций и отмена доступны через кнопку «Задачи».
Сохраняйте версии и наблюдения перед перезагрузкой страницы: несохранённые черновики
хранятся только в памяти открытого проекта.

## CLI

Сохранённую модель можно применить к новой записи без API, браузера и PostgreSQL.
Пример из корня репозитория после установки зависимостей:

```sh
uv run --project backend --frozen protocol-lab apply --model tests/fixtures/cli/length-model.json --capture tests/fixtures/framing/length-big.pcap --output validation.json
```

CLI использует тот же движок разбора и проверки, что и интерфейс. Подробности
и команды переноса проекта описаны в [документации CLI и экспорта](docs/portability.md).

## Разработка и документация

Основной стек: React + TypeScript + Vite, Python + FastAPI, PostgreSQL.

```sh
uv run --project backend --frozen ruff check backend scripts run.py
uv run --project backend --frozen pytest backend/tests
npm --prefix frontend test
npm --prefix frontend run build
```
