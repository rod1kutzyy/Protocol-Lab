# Интерпретации — формат interpretation-1

Модель содержит `schema_version`, `name`, отдельную конфигурацию `framing`, последовательные
`fields`, проверки `checks` и защитные пределы. JSON Schema: [interpretation.schema.json](interpretation.schema.json).
Pydantic дополнительно проверяет ссылки, уникальность имён, глубину и допустимость проверок.
GUI, CLI и загрузка моделей из переносимых проектов используют общий `load_model`.
До проверки схемы он отвергает повторные JSON-свойства на любом уровне и нестандартные
числа NaN/Infinity. В частности, два свойства `constant` в одном поле не выбираются
молча; CLI возвращает exit 2 без создания выходного файла.
Байты читаются через общий независимый движок Construct, без Python-кода из модели,
`eval`, файловых ссылок, импорта модулей или сетевых запросов.

## Поля

| kind | Параметры | Поведение |
| --- | --- | --- |
| int | name, width: 1/2/4/8, signed: true/false, endian: big/little | Последовательное чтение целого; опционально constant/minimum/maximum |
| bytes | name, length: число / формула / remaining | Сырые байты; optional constant_hex проверяет полное значение |
| array | name, count: число / формула, fields | Структура повторяется count раз; ссылки внутри элемента локальны |
| switch | name, selector, cases | Структура выбирается по ранее прочитанному целому; ключи cases — десятичные строки |

Формула имеет вид `{"field":"payload_length","multiplier":1,"add":0}` и означает
`значение × multiplier + add`. Ссылка должна вести на **предыдущее целое в той же структуре**.
Вложенная структура не обращается к полям родителя. Имена: латинская буква, затем до 63
букв/цифр/подчёркиваний; одинаковые имена в одной структуре запрещены.
`remaining` читает до конца текущего сообщения, также внутри вложенной структуры.
Неописанный вариант switch возвращает `unknown`, сохраняет уже прочитанные поля и остаток.

Целые в модели остаются точными JSON-числами, а **извлечённые целые** передаются как
десятичные строки: браузер не округляет значения uint64/int64. Редактор сохраняет исходные
числовые токены при форматировании и замене конфигурации фрейминга.
HEX-предпросмотр bytes ограничен 64 байтами, что отмечается `preview_truncated`;
полный диапазон доступен в HEX и источниках. У пустого поля length=0 нет SourceRange:
`anchor=null`, но его offset и длина видны.

## Проверки и неизвестные данные

Целые: `constant`, `minimum`, `maximum`. Байты: `constant_hex` (целые байты, без пробелов).
Проверки длины на верхнем уровне:
`{"kind":"length","field":"payload","expected":{"field":"payload_length"}}`.
Для bytes сравнивается число байтов, для array — число элементов, для switch — число
потреблённых байтов. Формула expected может ссылаться на целое верхнего уровня,
поскольку проверки исполняются после разбора всей структуры.

При нарушении константы/диапазона, отрицательной вычисленной длине или выходе поля за
сообщение результат `failed`. Поля, прочитанные до остановки, остаются фактами исполнения,
а непотреблённый остаток — отдельными диапазонами. Пропуски/усечения дают `unknown`,
конфликтующие данные — `ambiguous`; движок не выбирает один вариант и не подставляет нули.

Начиная с `interpretation-v2`, превышение защитных `max_array_items`,
`max_message_bytes` и `max_decoded_fields` даёт `unknown` с отдельным кодом
и `technical_limit`: name, observed, maximum (точные десятичные строки).
Превышение технического лимита не опровергает правило протокола.
Старые результаты `interpretation-v1` без этого поля читаются неизменными;
версии модели `interpretation-1` совместимы. [Изменения A0](inference-a0.md).
Неописанный известный хвост даёт `unknown`. Остатки фрейминга учитываются как
`not_applicable`, без попытки разбирать их как сообщения. Неопределённость данных имеет
приоритет над итоговым passed/failed; конкретная диагностика проверки остаётся видна.
Соседние неизвестные диапазоны одинакового статуса объединяются; исходные packet mappings
доступны через прежний `/streams/{id}/bytes`.

`passed` означает полное потребление сообщения и выполнение заданных проверок.
Это не доказательство истинного назначения поля. Обозначения полей задаёт инженер.
Проверка корпуса, гипотезы, сравнение запусков и stale-индикация относятся к этапу 8.

## Версии, хранение и API

Изменение модели сохраняется как новая immutable версия с parent_id, model_id, timestamp,
SHA-256 канонического JSON. Повторное сохранение того же содержимого в этой истории
возвращает прежнюю версию. Новая независимая модель получает новый model_id.
Результат разбора содержит version_id/hash, framing_run_id, capture_id/hash,
reconstruction_version и engine_version. Одинаковые входы возвращают прежний результат.
Миграция `0005_interpretations` добавляет таблицы, не переписывая старые данные.
Результаты лежат как immutable SHA-256-артефакты JSONL под относительным `derived/`.

- `GET /api/v1/interpretations/schema` — локальная JSON Schema, без БД.
- `POST /api/v1/interpretations/check` — `{document_json}`, valid и issues с путями, без БД.
- `POST /api/v1/projects/{id}/interpretations` — `{document_json,parent_id?}`, immutable версия.
- `GET /api/v1/projects/{id}/interpretations?offset=0&limit=100` — версии проекта.
- `GET /api/v1/interpretation-versions/{id}` — версия и точный документ.
- `POST /api/v1/framing-runs/{id}/interpretations` — `{version_id}`, отменяемая задача.
- `GET /api/v1/framing-runs/{id}/interpretations` — сохранённые разборы.
- `GET /api/v1/interpretation-runs/{id}` — источник/версии/счётчики.
- `GET /api/v1/interpretation-runs/{id}/results?offset=0&limit=100` — лёгкие сводки.
- `GET /api/v1/interpretation-runs/{id}/results/{piece_id}` — поля и неизвестные участки одного диапазона.

Настройки фрейминга модели должны совпасть с выбранным результатом; принадлежность
модели и записи одному проекту проверяется. Иначе API возвращает 422 до создания задачи.
Перед публикацией проверяются источник, версии, совпадение каждого сообщения с framing
anchor, полное покрытие потока и диапазоны полей. Наблюдения и action links не изменяются.
Отмена/сбой не публикуют частичный запуск и оставляют старые результаты доступными.

## Защитные пределы

Документ: до 131072 символов; max nesting 8 структур, 512 определений полей, 128 полей
на структуру, 32 варианта switch. Массив: по умолчанию 1024, максимум 4096 элементов.
Декодированных полей/неизвестных диапазонов: по умолчанию 4096, максимум 16384.
Ограничение числа декодируемых полей даёт explicit unknown с оставшимся диапазоном;
превышение числа неизвестных диапазонов или артефакта 256 МиБ завершает задачу ошибкой
без публикации. Размер сообщения задаёт FramingSpec (default 1 МиБ, max 16 МиБ).
Это ограничения реализации, не ограничения исследуемого протокола.

Результаты пишутся по одному сообщению; списка всех декодированных полей потока в памяти
нет. UI загружает сводки страницами и детали выбранного сообщения, виртуализирует списки.
Linux-профиль времени/RSS проверяется отдельно на этапе 10.
