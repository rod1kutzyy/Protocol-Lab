# Ручная проверка этапа 5

## Запуск

Из корня проекта установите зависимости и подготовьте `.env` по
[инструкции PostgreSQL](manual-stage-3.md#установка-и-postgresql).
Нужны работающий Docker Desktop либо собственная локальная PostgreSQL.

```sh
uv sync --project backend --frozen
cp -n .env.example .env
# Замените CHANGE_ME в .env своим паролем перед следующими командами.
docker compose up -d
uv run --project backend --frozen alembic -c backend/alembic.ini upgrade head
uv run --project backend --frozen uvicorn protocol_lab.api.app:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. После обновления применяйте миграции и перезапускайте
API. Текущая миграция `0003_investigation` добавляет журнал действий и время сессий,
сохраняя источники, восстановленные потоки и наблюдения предыдущего этапа.

Если API возвращает 503 «PostgreSQL is not configured», проверьте наличие
`PROTOCOL_LAB_DATABASE_URL` в `.env` в корне проекта и перезапустите API. При `Connection refused` проверьте `docker compose ps`
и соответствие порта БД в `.env`. Команда миграции сама PostgreSQL не запускает.

## Исходные байты и сравнение

1. На вкладке «Исследование» создайте проект; для открытия нажмите его в списке слева.
   Это зарегистрированный локальный проект. Восстановление переносимого архива — этап 9.
2. Импортируйте `tests/fixtures/tcp/ordered.pcap`, policy «Предупреждать».
   Дождитесь завершения, проверьте 5 пакетов и SHA-256. «Задачи» показывает детали
   jobs и позволяет отменять незавершённые операции.
3. Нажмите «Восстановить TCP». Выберите соединение `192.0.2.1:41000 ↔ 192.0.2.2:9000`.
   Фильтр порт=9000 находит его; порт=9001 скрывает. Сбросьте фильтры.
4. A→B показывает `HELLOWORLD`, B→A — `OK`. HEX и ASCII используют одни bytes.
   Время фильтров задаётся в UTC, границы времени включены; интервал пересекает
   время соединения. Сессии без временных меток не попадают в временной фильтр.
5. Выделите [0,5) через поля диапазона либо клик/Shift+клик. Нажмите источник:
   пакет #3, payload [0,5), file @304. Оригинальные bytes пакета подсвечены.
   Можно листать bytes пакета и источники больших выделений.
6. Сохраните наблюдение, затем «Запомнить для сравнения». Выделите [5,10).
   Сравнение HELLO/WORLD показывает различия в позициях 0,1,2,4; позиция 3 равна.
   Для сравнения можно выбрать другой поток; размер каждого диапазона ≤4096.
7. Ищите HEX `48 45 4C 4C 4F`: одно совпадение, смещение 0. Нажмите его для перехода.
8. Импортируйте и восстановите `tests/fixtures/tcp/gaps-overlaps.pcap`.
   В A→B: ABC [0,3), конфликт D/X [3,4), E [4,5), пропуск [5,8), IJ [8,10),
   усечение [10,13). Конфликт показан как ??, пропуски как —. Выделите [2,5):
   доступны оба варианта и все исходные передачи. Поиск `43 44 45` не даёт совпадения.

## Журнал действий и поправка часов

1. Вернитесь к ordered.pcap, выберите A→B и [0,10).
2. Загрузите `tests/fixtures/actions/clock-offset.csv` в «Журнал действий».
   Формат CSV, разделитель запятая; нажмите «Посмотреть поля».
3. Выберите время=when, действие=operation, параметры=args, формат=Unix, секунды.
   Импортируйте: две строки приняты, строка 3 отклонена с диагностикой.
4. Включите «По времени выделенных байтов», допуск=0. До поправки кандидатов нет.
   Сохраните поправку `-1000000000` ns. Теперь появляется строка 1 Set speed,
   параметр 1. При допуске 1 ms появляется и строка 2 с параметром 2.
   Исходные временные метки журнала сохраняются; используется log time + offset.
5. Выберите строку, напишите основание и нажмите «Привязать действие к выделению».
   Сохранённая связь содержит диапазон, версию tcp-v1 и exact packet sources.
   В списке связей нажмите «Открыть связанные байты», чтобы вернуться к этому диапазону.
6. Перезагрузите страницу и перезапустите API: проект, captures, потоки, журнал,
   поправка, наблюдение и связь сохранены. Jobs после рестарта API исчезают.
7. Повторный импорт тех же источников возвращает already_imported и существующий ID;
   прежние настройки импорта сохраняются. Не нужно заново создавать исследование.

Совпадение по времени — кандидат для проверки инженером, а ручная связь — запись
наблюдения. Они не доказывают значение протокольного поля. Фрейминг и модель протокола
начинаются в следующих этапах после ревью этого этапа.
