# Автоматический анализатор — A1

A1 добавляет bounded offline-поиск предложений поверх контрактов и воспроизводимой
выборки A0. Он использует существующие TCP, framing и source-provenance движки.
Кандидат — основанное на данных объяснение, а не подтверждённая семантика протокола.

## Реализовано

- Поиск фиксированных границ, полей длины с настраиваемыми смещением, шириной,
  endian, multiplier и adjustment, а также пар start/end markers.
- Поиск повторяемых областей относительно начала и конца найденного сообщения.
  Каждая область зависит от конкретного кандидата framing; она не утверждает
  назначение или ширину поля.
- Базовая оценка Shannon entropy для окна до 64 байт внутри сообщения с размером
  выборки и явным предупреждением, что значение не доказывает шифрование или сжатие.
- Проверка кандидатов тем же framing engine на всём явно выбранном discovery scope;
  известные пропуски и конфликты остаются `unknown`/`ambiguous`. Правило фиксируется
  до отдельного запуска на holdout или целевом корпусе.
- Frozen source/model/corpus snapshots, hashes, версии движков, evidence с исходными
  packet ranges, persistence в PostgreSQL, отменяемые jobs и UI для просмотра,
  навигации к байтам, holdout-проверки и черновика исполняемой модели.
- Offline CLI `infer` и `evaluate-candidate` используют тот же core engine.

Поиск ограничен настройками `SearchBudget` и `SearchSpace` в
`inference-spec-1`. Запуск сохраняет число рассмотренных уникальных правил,
неполные области и причины ограничений. Исчерпание бюджета не считается
опровержением правила. Идентичные предложения больше не расходуют бюджет повторно;
сумма испытаний по направлениям ограничена общим `max_rule_trials`.

## Границы A1

Детекторы `framing`, `structure` и `entropy` доступны. Семейства разделителей,
групп сообщений/opcode, счётчиков, токенов, checksum/CRC, временных связей,
действий и Data Mapping описаны контрактами, но ещё не реализованы. Для них API
возвращает `unsupported`; запуск не выдаёт отсутствие таких кандидатов за отсутствие
соответствующей структуры.

Поиск markers использует bounded n-grams и проверку предложенной геометрии на
выборке; это ранжирование гипотез, не статистическое доказательство. Структурные
области и entropy условны на сохранённых framing-кандидатах и ограниченной
детерминированной выборке. Короткие либо повторяющиеся данные могут оставлять
несколько равноценных объяснений. Независимость holdout проверяется по известным
ID/hash, истории использования и доступным TCP-координатам; непроверяемое
перекрытие явно остаётся exploratory/unverified.

В A1 исполняется и переносится только framing-кандидат. Аналитические кандидаты
областей пока нельзя напрямую оценить как отдельные правила; UI предлагает для них
свидетельства и сохраняет условную связь с framing. Они не компилируются в полную
модель сами по себе. После принятия кандидата инженер должен проверить черновик
модели на полном корпусе обычной validation-проверкой.

Следующие семейства и расширение DSL относятся к A2–A4 согласно
[ТЗ анализатора](automatic-analyzer-spec.md#13-порядок-реализации-и-критерии-готовности).

## Замер A1

Существующий замер [inference-a1.json](benchmarks/inference-a1.json) выполнен на
macOS ARM64 через файловый адаптер: 10 000 сообщений, 748 449 байт потока,
6,14 секунды, peak RSS 719,7 MiB, JSON output 62,9 MB. Правило длины найдено
среди первых пяти кандидатов. Поиск остановился на лимите 5 000 trials, поэтому
`search_complete=false`. Это локальный baseline без PostgreSQL, браузера и holdout;
он не подтверждает контрольный 4 vCPU / 8 GiB workload из ТЗ. Объём памяти и
evidence на таком небольшом корпусе остаётся заметной точкой для дальнейшей
оптимизации.
