# Ручная проверка этапа 7

Примените миграцию и перезапустите API/UI. `.env` в корне читается автоматически:

```bash
uv sync --project backend --frozen
docker compose up -d postgres
uv run --project backend --frozen alembic -c backend/alembic.ini upgrade head
uv run --project backend --frozen uvicorn protocol_lab.api.app:app --host 127.0.0.1 --port 8000
# Второй терминал:
npm --prefix frontend run dev
```

Откройте http://127.0.0.1:5173. Используйте новый тестовый проект, чтобы сохранять свои
исследовательские версии отдельно. Оригинальные PCAP при этом не меняются.

1. Импортируйте `tests/fixtures/framing/length-big.pcap`, восстановите TCP, выберите
   соединение и направление A → B.
2. Фрейминг: поле длины, offset=0, width=2, big endian, multiplier=1, adjustment=2.
   Постройте результат: три сообщения `[0,5)`, `[5,12)`, `[12,15)`.
3. Ниже результата откроется **Модель протокола**. Кнопка **Пример: поле длины**
   создаёт поля payload_length (uint16 big endian) и payload вычисляемой длины.
   **Проверить модель** показывает проверку схемы и ссылок. Ошибки подсвечиваются в Monaco.
4. **Сохранить новую версию**, затем **Разобрать сообщения**. Ожидается три результата
   «Правила выполнены». Выберите каждый: длины 3, 5, 1; HEX `414243`, `4445464748`, `5a`.
   Между сообщениями не требуется править модель.
5. Во втором сообщении кликните payload: выделится `[7,12)`; источники покажут пакеты
   #4 `[7,9)` и #5 `[9,12)`. Первый uint16 также пересекает два пакета.
6. В редакторе добавьте первому int-полю `"constant": 3`. Сохраните новую версию,
   разберите: один passed, два failed. Старый разбор доступен в списке, его значения прежние.
   Ошибка — нарушение заявленного правила, а не доказательство неверности исходных байтов.
7. Удалите часть JSON или задайте `length: {"field":"missing"}`. Проверка выдаёт ошибку;
   сохранить/применить эту модель нельзя. Выберите прежнюю версию, чтобы восстановить JSON.
   Cmd+A/Ctrl+A выделяет весь документ, Cmd+Z/Ctrl+Z отменяет редактирование; поиск и
   форматирование — стандартные команды Monaco.
8. **Пример: исходные байты** создаёт одно поле до конца сообщения. Для отдельного
   неизвестного хвоста опишите, например, только первые два bytes: остальные байты
   появятся в блоке **Неизвестные и неописанные участки** и доступны по клику.
9. Импортируйте `tests/fixtures/interpretation/arrays-variants.pcap`. Фрейминг тот же.
   В **Пример: массив и варианты** добавьте первым полем перед count:
   `{"kind":"int","name":"payload_length","width":2,"signed":false,"endian":"big"}`.
   Сохраните, примените: count=2,1,0; в первом сообщении entries[0].body.value=-2,
   entries[1].body.raw=4142; во втором value=4660. Пустой массив имеет length=0 и anchor=null.
10. Импортируйте `arrays-new-parameters.pcap`, выполните тот же фрейминг, выберите **ту же
    сохранённую модель** проекта. Без правок count=1, entries[0].body.raw=4344.
11. Для `tests/fixtures/tcp/gaps-overlaps.pcap` примените fixed size=5 и модель «исходные
    байты»: результаты ambiguous, unknown, not_applicable. Пропуски и конфликтные варианты
    не становятся нулями или однозначными полями.
12. Измените framing в сохранённой модели. UI объяснит несовпадение. Можно использовать
    текущий framing и сохранить новую версию либо **Построить фрейминг модели**, выбрать
    созданный результат выше и открыть нужную версию модели.
13. На длинной записи отмените задачу до сохранения: прежние разборы и наблюдения доступны,
    отменённый запуск отсутствует среди результатов. После рестарта API/UI выберите проект,
    поток, сохранённый framing, версию модели и разбор — значения и source anchors сохраняются.

Объяснение полей, проверок, ограничений и endpoint-ов: [interpretations.md](interpretations.md).
Это разбор одного выбранного потока; гипотезы и проверка корпуса будут на этапе 8.
PPP/MPTCP не добавлены: ранее предоставленный iperf PPP capture по-прежнему требует
отдельной поддержки link layer. Для этого ревью используйте перечисленные синтетические PCAP.
