# Ручное ревью этапа 8

Примените добавляющую миграцию и перезапустите API. `.env` читается автоматически.

```bash
uv run --project backend --frozen alembic -c backend/alembic.ini upgrade head
uv run --project backend --frozen uvicorn protocol_lab.api.app:app --host 127.0.0.1 --port 8000
# Другой терминал:
npm --prefix frontend run dev
```

Для первоначальной установки PostgreSQL и зависимостей используйте [manual-stage-7](manual-stage-7.md).
Откройте http://127.0.0.1:5173 и создайте отдельный тестовый проект.

1. В **Исходные данные** импортируйте `tests/fixtures/framing/length-big.pcap` и
   `tests/fixtures/interpretation/arrays-new-parameters.pcap`. Для обеих записей выполните
   **Восстановить TCP**. Не объединяйте их соединения по одинаковым адресам/портам.
2. Выберите первое направление A → B, постройте length framing: offset 0, width 2,
   big endian, multiplier 1, adjustment 2. Ожидаются `[0,5)`, `[5,12)`, `[12,15)`.
3. Создайте модель с `int n` (width 2, signed false, big endian, **constant 3**) и
   `bytes payload` с `length: {"field":"n"}`. Framing модели соответствует шагу 2.
   Сохраните версию. Это намеренно слишком узкое правило для проверки контрпримера.
4. Выделите `[0,2)` и сохраните наблюдение: «Прочитано 0003 перед ABC».
   В **Гипотезы и проверка корпуса** сформулируйте гипотезу, основания и область,
   выберите это наблюдение. Добавьте неизвестные случаи и сохраните. Карточка содержит
   evidence link; он возвращает к тем же двум байтам, разделённым между пакетами.
5. В **Корпус и выполнение правил** выберите две записи, direction A → B, без остальных
   фильтров; сохраните версию корпуса. Кнопка «Выбрать загруженные» выбирает только
   загруженные страницы — для большего списка сначала используйте «Загрузить ещё».
6. Выберите сохранённую модель и нажмите **Проверить весь корпус**. Ожидается:
   1 Passed message, 3 Failed messages, 21 включённая позиция потока; пустые исключённые
   направления дают Not applicable с нулём bytes. Сводка включает все строки, не только видимые.
7. Выберите Failed `[0,6)` дополнительной записи. В деталях `n=4`, поле `[0,2)`.
   Клик по полю открывает HEX `00 04`, packet #3, file offset 304. Нарушена константа 3;
   это не изменение исходной записи. Вкладка корпуса сохраняет выбранный запуск при навигации.
8. Вернитесь к редактору модели в **Исходные данные**. Если у дополнительной записи ещё
   нет сохранённого framing preview, постройте его с теми же length settings. Откройте старую
   версию модели, удалите constant 3 и сохраните **новую версию**.
9. Вернитесь к корпусу: старый запуск отмечен устаревшим из-за новой модели; он сохраняет
   прежние значения. Выберите новую модель и тот же корпус, повторите запуск: 4 Passed.
   Откройте старый запуск и сравните с новым: **3 перехода Failed → Passed**, одинаковые
   source ranges. «Открыть прежний/новый результат» показывает соответствующую версию запуска.
10. Уточните гипотезу вручную: основания, scope, evidence и противоречия. Исполнение
    правила само не помечает её подтверждённой. Прежняя карточка остаётся в истории.
11. Измените порт корпуса на 1, сохраните новую версию. Старый запуск устарел по corpus
    version. Новый учитывает все 21 позиции как excluded / Not applicable; selected bytes = 0.
    Фильтр **списка результатов**, напротив, не меняет полную сводку.
12. Проверьте неполные случаи отдельным корпусом: `framing/length-incomplete.pcap`
    (length rule даёт 3 unframed Unknown bytes), `unsupported-link.pcap` (явная диагностика),
    и запись, для которой **не запускали TCP reconstruction** (Unknown, extent неизвестен).
    Остальные пригодные потоки проверяются. После восстановления последней записи старый
    запуск устарел по входам; повторный запуск фиксирует новые inputs.
13. Для `tcp/gaps-overlaps.pcap` используйте fixed size 5 и одно raw bytes поле remaining:
    видны Ambiguous/Unknown, отдельные counts пропусков и конфликтных bytes. Нулей вместо
    пропусков нет. Для проверки изоляции ошибки framing задайте max_pieces=1 на корпусе
    первых двух записей: первый поток Unknown целиком, второй короткий message Passed.
14. На достаточно большом корпусе отмените запуск до committing: результата запуска нет,
    прежние разборы/гипотезы/наблюдения доступны. После рестарта выберите проект, сохранённый
    corpus/run/hypothesis — значения и источники доступны, несмотря на сброс registry задач.

Полный формат, статусы, актуальность и пределы: [validation.md](validation.md).
Не изменяйте оригиналы для ручного теста ошибок: integrity/cancel/rollback проверены автоматически
на изолированных тестовых данных. Export/report/CLI относятся к следующему этапу.
