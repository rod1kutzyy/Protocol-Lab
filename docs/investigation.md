# Исследование: контракты и ограничения этапа 5

Интерфейс использует сохранённые результаты tcp-v1. Критерии принятия R1/R2:
выделенные bytes приводят к исходному пакету; поиск и сравнение сохраняют неопределённость;
журнал можно сопоставить по времени и связать с устойчивым диапазоном вручную.

## API

Все маршруты имеют префикс `/api/v1`. Полные типы: [OpenAPI](openapi.json).

| Маршрут | Поведение |
| --- | --- |
| GET projects/{id}/sessions | capture_id, address (IPv4), port, start_ns/end_ns; пересечение времени, включённые границы |
| GET packets/{id}/bytes?offset=&length= | Оригинальные bytes кадра, длина 1–4096, без выхода за captured_length |
| POST streams/{id}/search | pattern_hex 1–256 bytes, start; фоновая отменяемая задача |
| POST projects/{id}/action-logs/preview | multipart file, format csv/json, delimiter; имена полей и число строк |
| POST projects/{id}/action-logs | multipart file, format, mapping_json; отменяемый импорт |
| GET projects/{id}/action-logs | Сохранённые settings/hash/path, row diagnostics, offset/revision |
| GET projects/{id}/actions | Все принятые события, опциональный log_id |
| PATCH action-logs/{id}/clock | clock_offset_ns как строка, expected_revision; 409 при устаревшей ревизии |
| GET streams/{id}/actions | offset, length ≤65536, window_ns ≤60000000000; временные кандидаты |
| POST projects/{id}/actions/{id}/links | ObservationInput: text, anchors; атомарно сохраняет наблюдение и связь |
| GET projects/{id}/action-links | Сохранённые связи со stable observations/sources |

Страничные списки используют offset/limit (до 1000, интерфейс запрашивает 100), next_offset=null в конце.
Для временных кандидатов page отделён от stream offset. Время передаётся строкой
наносекунд, чтобы не округлять его через JavaScript Number.

Поиск возвращает matches (смещения потока), pattern_hex, complete, next_offset,
skipped_bytes и skipped_ranges. До 1000 совпадений и 100 диагностических диапазонов
на странице, продолжение с next_offset. Неопределённые bytes разрывают шаблон;
пакетные границы и границы страниц достоверного непрерывного потока — нет.
Результат поиска живёт в job; исходные потоки остаются в PostgreSQL/файлах.

## Журналы

UTF-8 (BOM допустим), CSV с заголовком и запятой/точкой с запятой/табуляцией;
JSON — массив объектов, параметры могут быть вложенным JSON.
Mapping задаёт timestamp_field, label_field, optional parameters_field,
timestamp_format и CSV delimiter. ISO 8601 требует timezone и ≤9 дробных цифр;
unix_s/ms/ns разбирается точно, без float и без округления арифметическим
контекстом Decimal. Дробные наносекунды отклоняются. Числовые параметры JSON
сохраняют числовой тип и точность, в том числе во вложенных объектах/массивах. Временная метка в пределах signed int64 ns.

Защитные пределы: файл 16 MiB, 100000 строк, 128 полей, имя поля ≤200 символов,
название действия ≤500, параметры JSON ≤10000 символов. CSV reader также ограничивает
размер одного поля 131072 символами. Ошибка формата/предела завершает задачу failed;
некорректная отдельная строка получает диагностику, остальные события сохраняются.
Показываются до 100 row diagnostics, число отклонённых и полнота списка явные.

Оригинал журнала сохраняется без переписывания, с SHA-256 и относительным путём.
Одинаковый hash в проекте не создаёт второй журнал и возвращает прежний mapping.
Отмена до committing не публикует журнал; существующие результаты остаются доступны.
Поправка часов хранится отдельно, исходные timestamps не меняются.

Временные кандидаты строятся по min/max timestamps всех источников выделенного
диапазона, включая retransmissions, с заданным допуском. Packet timestamps без времени
считаются и явно показываются; при полном отсутствии времени кандидатов нет.
Метод `time_window_only_not_semantic_proof` не устанавливает семантическую причинность.
Manual link использует ту же проверку scope/version/source, что обычное наблюдение.

## Загрузка и целостность

HEX: виртуальные строки по 16 bytes, окно 65536 позиций, запросы страниц по 4096
только для видимых строк. Переход к любому offset не требует создавать DOM для
целого потока. Источники больших выделений листаются страницами по 4096 позиций;
сравнение ограничено 4096 на диапазон, наблюдение/ручная связь — 65536.
Неизвестные/конфликтующие bytes никогда не считаются равными известным bytes.

Первое чтение capture в процессе проверяет SHA-256. Повторные чтения используют
кэш по inode/size/mtime_ns/ctime_ns; изменение stat вызывает повторную проверку.
Новый worker проверяет исходник заново. Реконструкция, manifest и originals предыдущих
этапов не перезаписываются. Проверка portable archive предусмотрена этапом 9.
