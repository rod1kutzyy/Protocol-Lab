# Навигация и рабочая область

UI разделён по задачам инженера. Выбор проекта и создание/восстановление находятся
в верхней панели; постоянное меню слева содержит пять разделов.

| Раздел | Возможности | Требования |
| --- | --- | --- |
| Данные | PCAP/PCAPNG, checksum policy, диагностика, восстановление TCP, фильтры соединений; импорт CSV/JSON и поправка часов | R1, R2 |
| Исследование | HEX/ASCII, поиск, диапазоны, исходные пакеты, наблюдения, сравнение; журнал действий и ручные привязки; гипотезы с версиями и evidence | R1, R2 |
| Модель | Независимые вкладки «Границы сообщений» и «Поля и правила», immutable framing runs, Monaco, JSON Schema, версии, разбор, поля и неизвестные диапазоны | R3 |
| Проверка | Корпус и фильтры, полное покрытие, пять статусов, контрпримеры, актуальность и сравнение запусков | R4 |
| Результаты | Целостность, снимок, ZIP, Markdown, JSON-модель и JSON результатов | R5, R6 |

Выбор строки TCP-соединения открывает исследование. Контекстная панель показывает
выбранные endpoints, capture ID, направление и диапазон. Роли A/B не выдаются за
известные client/server. Диагностика неопределённости остаётся в списке соединений
и рядом с байтами. Источники выделения находятся в инспекторе справа; на узком
экране он располагается под HEX. Сравнение раскрывается кнопкой и не теряет
опорный диапазон при закрытии.

Разделы имеют URL `#data`, `#research`, `#model`, `#validation`, `#results`.
Назад/вперёд в браузере возвращают раздел, не перезагружая проект. После перехода
фокус перемещается на заголовок. Навигация остаётся доступна на узком экране.

## Сохранение контекста

`WorkspaceScreen` скрывает разделы без размонтирования форм. Вложенная видимость
учитывает скрытие родительского экрана; при возврате восстанавливается прокрутка
самого экрана и виртуальных списков. Поэтому переключение разделов/инструментов
и открытие фоновых задач сохраняет выбранные результаты, фильтры, action selection,
черновики наблюдений, гипотез, корпуса, импорта и состояние Monaco.

`WorkspaceState` хранит черновики отдельно по stream/framing/source anchor внутри
открытого проекта. При переключении направлений или переходе к другому источнику
редакторы не накапливаются в DOM; при возврате восстанавливаются текст модели,
настройки фрейминга, поиск и черновик наблюдения. Ключ source включает версию
восстановления и диапазон; заметка не перепривязывается к другим байтам.

Это память текущего открытого проекта, а не сохранённая версия исследования.
Перезагрузка страницы или открытие другого проекта сбрасывает несохранённые
черновики. Сохранённые наблюдения/версии/запуски остаются в PostgreSQL. Zustand,
как и раньше, сохраняет текущие project/capture/session/stream/range и опорный
диапазон в localStorage. URL сохраняет открытый раздел. Повторный выбор уже
выбранного объекта не сбрасывает дочерний контекст.

Ссылки из гипотез, action links, framing/decoded fields и контрпримеров открывают
исследование и точный исходный диапазон. Возврат в модель/проверку сохраняет форму
и выбранный запуск. Для результатов без потока открываются исходные данные.

Кнопка «Задачи» доступна в шапке. Исследование остаётся смонтированным во время
просмотра задач; прогресс выбранной задачи, ошибка и отмена доступны также в
постоянной нижней строке. Работают прежние process jobs/SSE и правила отмены.

## Проверка

`npm test` проверяет selection invariants и соответствие URL разделам.
`npm run test:e2e` включает UI regression suite `workspace.spec.ts` с детерминированными
REST-ответами без БД: черновики, фильтры, файлы импорта, выделение, comparison,
Monaco, прокрутка, задачи, action/hypothesis source navigation, направления,
узкие экраны 375×812 и 812×375 с reduced motion. Эти проверки не заменяют ядро.

Реальный `research.spec.ts` обновлён под новую навигацию: импорт → наблюдение →
журнал/привязка → модель → гипотеза → корпус/контрпример → версия модели →
сравнение запусков → ZIP/report → restore → CLI. Для его запуска требуется
`PROTOCOL_LAB_TEST_DATABASE_URL` и `scripts/run_e2e.py`, которые изолируют данные
в двух тестовых PostgreSQL schemas. Исследовательская БД для теста не выбирается.

## Результат проверки 2026-10-15

- `npm run typecheck` — успешно.
- `npm test` — 19/19, 7 файлов.
- `npm run build` — успешно; предупреждение Vite о большом Monaco chunk остаётся.
- `scripts/run_e2e.py` — 6/6 Playwright-сценариев, без skipped. Использован отдельный
  временный PostgreSQL 17 в Docker, без volume mounts и доступа к пользовательским
  данным. Runner создал/мигрировал две изолированные схемы и удалил их после теста.
- Просмотрены снимки desktop и 375 px; автоматическая проверка выполнена также
  для 812×375 и reduced motion. Runtime page errors и внешние HTTP-запросы отсутствуют.

Python unit-тесты в этой UI-правке не запускались; backend и API-контракты не менялись.
В dev-логах Monaco есть предупреждение об отсутствующем source map у bundled marked;
оно не мешает загрузке редактора и выполнению тестов.
